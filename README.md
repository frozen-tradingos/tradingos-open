# Trading OS Open

在本地研究美股，查看预测依据，记录自己的交易计划并复盘。使用你自己的模型账号和 Robinhood 数据权限。

Local-first trading research: TS forecasts, conditional setups, trading plans and reviews. Bring your own model and Robinhood access.

**Windows x64 · 只读研究 · MIT · v0.1.0-preview.2**

[下载预览版源码包](https://github.com/w1113009511-svg/tradingos-open/releases/tag/v0.1.0-preview.2) · [安装步骤](#首次安装) · [反馈问题](https://github.com/w1113009511-svg/tradingos-open/issues)

## 可以用它做什么

- **预测与条件研究**：查看 TS 市场判断、目标交易日、触发条件和失效条件，保留判断依据。
- **交易计划与复盘**：记录交易理由和风险限制，回看原始判断与后续市场记录。
- **行情和持仓工作区**：提供 SPY / QQQ 图表、Robinhood 只读适配和可选 Finnhub 新闻入口。
- **自己的本地研究环境**：独立保存数据和授权；附带 Codex Skill，可用自然语言检查准备状态、研究市场或整理复盘。

**当前是实验预览版。** 已通过 Windows 独立副本的安装、构建和离线测试；真实新用户券商授权、行情读取到首个自然预测的完整流程仍待验收。首次需准备运行环境，模型和数据可能收费。不提供自动下单，不保证预测准确或盈利。

Windows x64 preview; Robinhood is the only implemented broker adapter. Live authorization, market data and a first natural forecast remain unverified end to end. Research only; no automated orders or performance guarantee.

## 支持范围

| 部分 | 本候选包的范围 |
| --- | --- |
| 总览、市场、持仓、研究与复盘界面 | 随配套程序提供，空白启动不展示个人历史 |
| TS 预测管线 | 保留原有 A1/A2/TS/复核/风控合同；需要用户自己的模型和行情授权 |
| 券商 | 当前适配 Robinhood 官方 MCP，严格只读；不是所有券商通用 |
| 行情 | 使用该券商实际允许读取的数据；权限、交易时段及新鲜度不足会阻断 |
| 新闻 | 可选 Finnhub，用户自备密钥并遵守其授权范围 |
| 模型 | 用户自己的 Codex 登录；额度及费用由其模型服务决定 |
| 账户、计划、复盘 | 保存在当前解压目录的独立数据区；不是云端多租户服务 |
| 自动分析 | 默认关闭，必须由用户明确启用当前会话 |
| 下单、跟单执行 | 不提供，券商写操作禁止 |
| SnapTrade、邮件注册、收款、域名、云部署 | 不接入，也不是本包的安装步骤 |

“只要授权就能使用”是要达到的体验，不代表可以省略首次环境准备，也不代表数据或模型免费。不要购买未经确认的套餐。

## 首次安装

1. 解压到一个自己的普通文件夹，例如 `D:\02_项目\TradingOS-Open`。不要解压到旧 Trading OS 目录，也不要把数据目录做成指向其他项目的链接。
2. 准备 Node.js 24 LTS、pnpm 11.16.0、Python 3.13。只从官方渠道安装；首次准备不需要购买服务。
3. 双击 `Start.cmd`，在菜单中先准备依赖和界面，再设置本地访问密码。
4. 可先打开空白工作区。地址固定为 `http://127.0.0.1:4160`；端口被占用会停止，不会接管已有进程。
5. 要使用真实研究，再完成自己的模型登录和 Robinhood 官方只读授权。不要在聊天、截图或问题反馈里发送密钥、验证码、授权链接。
6. 根据需要配置自己的新闻源，在菜单 9 填写并确认自己的研究资金和风险限额，再从菜单 8 明确启用本次会话的实时只读分析。没有完成的项目继续显示未就绪；没有推荐金额，不替你批准交易。

设置菜单顺序是 **1 → 2 → 3 → 4 → 9 → 6 → 8**；只想先看界面则用菜单 7，不会自动开始行情或预测。模型和券商登录要在各自官方页面由本人确认；不需要邮箱注册本地账号，也不要沿用别人的授权目录。授权页若要求新开户、扩大权限、充值或购买套餐，先停止，核对服务条款与费用。

安装器会检查已有的 Python 3.13：先找 Windows 的 `py` 启动器，再找 `python.exe` / `python3`，最后尝试使用已存在的 uv 环境。不会为你偷偷下载新 Python 或升级全局工具。

本机管理员以外的人不应访问此目录。不要把 `web/data` 同步到公开网盘或提交 Git。程序不会替你连接原有个人版，也不会安装自动启动任务。

启动器使用独立Windows Job管理应用树。按Ctrl+C、正常结束或启动器意外退出时，会回收本副本的分析子进程，不按进程名终止其他软件。

开发者可从本包根目录使用：

```text
pnpm deps
pnpm build
pnpm setup
pnpm doctor
pnpm start
```

Python 的具体环境准备由设置菜单完成；离线诊断会逐项列出缺失项。`pnpm start` 仅打开空白/离线模式，不等于已完成授权或开始生成预测。

开启真实分析后，先在市场页检查行情来源和时间，再在研究页查看自然时段产生的原始预测、目标交易日与条件。休市、权限不足或数据不齐时可能没有新预测；等待下一个正常检查时点，不补造昨天或错过时段的结果。前一晚的次日预测不是此刻开仓信号。首次自然预测仍需实际授权后验收，本候选的离线测试不能替代它。

菜单 8 会启用整套研究流程，并非免费行情探针。即使最后是 `NO_TRADE`，模型分析也可能使用订阅额度或产生服务商费用。请先确认自己的计费方式；本包不替你开通 API 计费或购买数据。源码公开不代表真实预测已经验证成功。

菜单 9 只创建本人的第一版研究档案，不覆盖既有版本。后续风险资料修改需要追加版本流程；当前没有一键迁移私人版历史的功能。

官方准备说明：[Node.js](https://nodejs.org/en/download)、[pnpm](https://pnpm.io/installation)、[Python](https://www.python.org/downloads/)、[Codex 登录](https://learn.chatgpt.com/docs/auth)。

## Skill 怎么用

Skill 在 `.agents/skills/tradingos-research/`，与程序一同提供。在 Codex 中打开这个项目目录即可按仓库范围发现；它不会把程序、模型或数据订阅凭空安装好。

可直接说：“检查这个 Trading OS 包的准备状态”“根据真实证据研究今天的市场”“复盘这次计划”。Skill 先检查来源和授权，不会把示例分析写成真实结果。

## 数据和授权怎么隔离

- 所有运行数据都留在本副本的 `web/data/`；Python 运行态也在其中。
- 模型与券商使用两个独立的本包授权目录，不继承其他项目或用户全局授权。
- 新库默认空白，不预置任何人的持仓、本金、风险额度或交易理由。
- 安装、构建、离线诊断和自动测试不调用真实券商或模型。
- 缺少凭证、时效不足、合同不满足时停止生成可交易结论。真实数据产生后，也不能据此保证准确或盈利。

新预测会绑定本机实际的核心源码、网站源码和构建产物指纹；源码清单存在时还会逐文件核对。源码 ZIP 不冒充 Git 提交，源码或构建在启动后变化时停止提升为可信记录；旧记录不会回填升级。这里的“可信”只指本机来源与因果记录一致，不是发布者签名、安全认证、实际模型调用证明或预测准确率保证。

## 本地检查与打包

```text
pnpm test
pnpm test:web
pnpm check:package
pnpm package
```

另外还要运行 `v2-reference` 内的 Python 回归。打包采用白名单，不包含 Git 历史、依赖目录、私密配置、数据库、授权缓存、日志和本地工作文件。ZIP 内生成文件哈希清单。

安装成功、离线测试通过、真实授权通过、自然预测产生，是四种不同的结果。实际完成情况以本地交付报告为准；未做真实授权和自然时段验证时，不能称为“已全功能验收”。
